# Daily post-game chat

A Nostr identity (including the automatically generated anonymous session key) and a server-verified private completion unlock today’s single room, for wins and exhausted guesses alike. Public score posts alone do not qualify. The existing completion validator recomputes outcomes from signed ordered guesses; this is casual spoiler protection, not proof that someone played without assistance.

The browser calls same-origin `POST api/chat/rooms`, `read`, and `send`. These requests are signed kind 30078 events with the sole schema tag `word5.chat.v1`, a matching action, and a random 128-bit nonce. Nothing is published to Nostr relays. `rooms` retrieves only the current UTC puzzle’s key, date and answer after verifying the authenticated player completed it. There is no room list or previous-day access. Identity changes clear cached keys and displayed messages.

Each UTC puzzle period has one random 256-bit AES-GCM key, separate from Nostr identity keys. Browser encryption uses a fresh 96-bit IV and authenticates the schema, period, sender public key, and nonce as additional data. The server stores signed ciphertext events. Readers verify the sender signature and event hash before decryption and render text through `textContent`.

Keys are stored in browser sessionStorage under the signing identity. The server retains its shared key in SQLite; it can decrypt messages, and recipients can share their key or retain copies. This is the accepted casual privacy boundary. Do not describe it as encryption that hides content from the server.

Rooms expire exactly at `(period + 1) * PERIOD_MS`, the instant the next word begins at 00:00 UTC (08:00 Perth). Startup, every chat API access and a one-second idle timer delete old rooms and messages. Completion records remain score history, but cannot recreate expired rooms. Browser startup, identity changes, focus/resume and a one-second timer remove expired keys, drafts and room UI.

Limits: 200 messages per room, 2000 UTF-8 plaintext bytes in the browser, 4096 ciphertext base64 characters, 8000 request bytes read with a bounded stream, 40 signed requests per identity per minute, and 10 sends per minute with at least two seconds between sends. Signatures must be within 60 seconds; accepted request IDs are retained for 120 seconds to reject replay across restarts. Rate records contain no keys, message plaintext, or membership. Session, NIP-07 and bunker identities poll reads every ten seconds. Amber uses the explicit Refresh messages button instead of automatic background signing prompts. Opening chat and sending messages still require signer approval. Amber full-document callbacks resume the exact staged request (including nonce, timestamp and encrypted send payload) for the same identity and UTC period. Only ciphertext is staged; plaintext drafts are never persisted. Approvals older than the server’s 60-second window are discarded and the UI offers an explicit fresh retry. Cancellation clears only that operation’s staging, so an older response cannot remove a newer request.

Run `bun run test` for isolated database eligibility, authenticity, replay, encryption, expiry, storage cleanup and existing regressions. `test/browser-chat.smoke.ts` is an optional browser integration harness; pass `WORD5_PLAYWRIGHT_MODULE` pointing to an installed Playwright module. It uses a temporary database and in-memory test identities, without altering the managed app's player data.

`test/browser-chat-amber.smoke.ts` exercises the real Amber browser intent/return contract with genuine signatures through full-page login, rooms, read and encrypted send callbacks, expiry/cancel recovery and rollover during signer approval. It uses an isolated in-memory DB. Physical Android app switching and approval still need device review.

Chat sender headers resolve verified kind 0 Nostr display names and HTTP(S) profile photos through the shared profile loader. Missing/invalid profiles keep an identity fallback; broken images keep initials. Today’s `1/6`–`6/6` or `X/6` result comes from the existing player-history report only when its identity, current period and completed status match. No guesses are fetched or displayed. Optional metadata loads after messages, with three concurrent sender lookups, bounded queue/cache and timeouts; unavailable sources leave messages usable. Delayed results cannot update a different account or expired room.

`test/browser-chat-senders.smoke.ts` covers genuine signed kind 0 relay profiles, own/other display names, photos, win/loss badges, missing/forged metadata, broken/unsafe images, unavailable/invalid outcomes, deduplication, profile force-refresh preservation, mobile layout, scroll stability and delayed metadata after rollover/account change. Its DB, relay and identities are isolated fixtures.
